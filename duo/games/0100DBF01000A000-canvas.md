# Burnout Paradise — the Duo aspect lever (canvas size)

Build `74570fa2709ed714006cd65c42a97dc6` (v0, `main` at
`/path/to/work/0100DBF01000A000_build/extract/v0/ExeFS/main`).
Offsets are **image offsets**: text `0..0x967040`, rodata `0x968000..0xcd37b8`,
data `0xcd4000..0x11fad08` (above that is BSS).

## 1. NVN is resolved by name, into BSS through GOT slots

The resolver (`~0x5e8000`…`0x5e9400`) walks the NVN name table and, for each proc, does

```
adrp x1,<page>; add x1,x1,#<off>; mov x0,x20; blr x19     ; nvnDeviceGetProcAddress(name)
adrp x8,#0x11ec000; ldr x8,[x8,#<slot>]; str x0,[x8]      ; store through the GOT slot
```

so a slot is named by its **GOT offset** `0x11ec000+<slot>`; the GOT entry holds a BSS
address (an `R_AARCH64_RELATIVE` addend), and callers do `ldr x8,[x8,#slot]; ldr x8,[x8];
blr x8`. Verified slots:

| GOT slot | proc |
|---|---|
| `0x11ec628` | `nvnWindowBuilderSetDevice` |
| `0x11ec630` | `nvnWindowBuilderSetDefaults` |
| `0x11ec638` | `nvnWindowBuilderSetNativeWindow` |
| `0x11ec640` | `nvnWindowBuilderSetTextures` |
| `0x11ec688` | `nvnWindowInitialize` |
| `0x11ec8e8` | `nvnTextureBuilderSetSize2D` (never called: one store, no load) |

`[nvn] WindowInitialize … first WxH` (`dm/gfx/nvn/hle_nvn.c:1290`) therefore reports the
size of the first swap-chain texture the game built — and in this build that size is a
hard-coded immediate.

## 2. The swap chain

`0x5ed2f0` (called once from `0x5ecfe8`) builds the three presentation textures and the
window:

```
0x5ed308  mov  x22,#0x780             ; 1920
0x5ed30c  movk x22,#0x438,lsl #32     ; 1080   → x22 = 0x0000043800000780
0x5ed31c  stp  x22,x8,[sp,#8]         ; descriptor {w=1920, h=1080, 1, 1, …}   (texture 0)
0x5ed35c  blr  x8                     ; [vtable+0x40] create surface
0x5ed3e4  stp  x22,x8,[sp,#8]         ; same descriptor                        (texture 1)
0x5ed49c  stp  x22,x8,[sp,#8]         ; same descriptor                        (texture 2)
0x5ed638  ldr  x8,[x8,#0x630]; blr    ; nvnWindowBuilderSetDefaults(builder=sp+8)
0x5ed64c  ldr  x8,[x8,#0x628]; blr    ; nvnWindowBuilderSetDevice  (builder, device)
0x5ed664  ldr  x8,[x8,#0x638]; blr    ; nvnWindowBuilderSetNativeWindow(builder, window)
0x5ed67c  ldr  x8,[x8,#0x640]         ; nvnWindowBuilderSetTextures(builder, 3, array)
0x5ed698  ldr  x8,[x8,#0x688]; blr    ; nvnWindowInitialize(window=obj+0x158, builder)
```

The descriptor's first two words are the width/height, and all three textures reuse the
same `x22`, so **one** immediate pair sets the whole swap chain.

## 3. The game's display size

`0x1ad70` (called from `0x116a28`) is the display-size setter. It queries the operation
mode through the PLT stub `0x965570`, which is `_ZN2nn2oe16GetOperationModeEv`
(JUMP_SLOT GOT `0x11e18e0` — resolved from the dynamic section), and selects:

```
0x1ad78  bl   0x965570              ; operation mode (1 = console)
0x1ad84  mov  w8, #0x500            ; 1280
0x1ad88  mov  w9, #0x780            ; 1920
0x1ad8c  cmp  w0, #1
0x1ad90  csel w8, w9, w8, eq        ; width  = mode==1 ? 1920 : 1280
0x1ad9c  str  w8, [x11]             ; *0x11fcfc0 = width
0x1ada8  mov  w10,#0x2d0            ;  720
0x1adac  mov  w8, #0x438            ; 1080
0x1adb0  csel w8, w8, w10, eq       ; height = mode==1 ? 1080 :  720
0x1adb8  str  w8, [x9]              ; *0x11fcfc8 = height
```

(`0x11e29f8`/`0x11e2a00` are the GOT slots; their `R_AARCH64_RELATIVE` addends are
`0x11fcfc0`/`0x11fcfc8`.) Two consumers prove these are the screen size:

* `0x1b320` — the aspect getter: `(float)*width / (float)*height`, and
* `0x1b350` — the viewport-rect builder, which letterboxes with the same two words.

## 4. The patch

Three words, heights only (widths stay 1920/1280 so the horizontal pixel scale is 1:1):

| offset | original | new | meaning |
|---|---|---|---|
| `0x1ada8` | `0x52805a0a` `mov w10,#0x2d0` | `0x5280708a` `mov w10,#0x384` | handheld display height 720 → 900 (1280×900) |
| `0x1adac` | `0x52808708` `mov w8,#0x438` | `0x5280a8c8` `mov w8,#0x546` | console display height 1080 → 1350 (1920×1350) |
| `0x5ed30c` | `0xf2c08716` `movk x22,#0x438,lsl #32` | `0xf2c0a8d6` `movk x22,#0x546,lsl #32` | swap-chain texture height 1080 → 1350 |

`0x5ed308` (`mov x22,#0x780`) is the width half and stays. 1920×1350 = 1.42222 against the
Duo's 2853×2007 = 1.42152 (0.05 % off, the tolerance `duo/DESIGN.md` accepts).

Both the display size and the swap chain must move together, exactly as in Scott Pilgrim:
patch only the swap chain and the game renders 1080 into a 1350-tall texture; patch only
the display size and the texture stays 1080.

The 16:9 constant row this build already has in `duo/research/games.tsv` (`0xaab614`, the first of
three) stays valid and is complementary: the canvas now carries the Duo ratio, and the
projection aspect is then set to the drawable's ratio, 0.05 % away.

## 5. Left alone on purpose

`0x2b01e0` and `0x5e5f18` select **1600×900 / 1280×720** (`mov w8,#0x500; mov w9,#0x640;
csel w8,w9,w8,ne; mov w9,#0x384; csel w9,w9,w10,ne`) and store into one object's
`+0xc56340`/`+0xc56344`, not into the screen-size globals. They are left at 16:9 because
nothing shows them feeding the swap chain or the aspect getter. If the picture turns out to
be composed through that buffer, patch it the same way: `0x2b01e4` `mov w9,#0x640`
(1600, unchanged), `0x2b01ec` `mov w10,#0x2d0` → `#0x384` (720 → 900) and `0x2b01f4`
`mov w9,#0x384` → `#0x465` (900 → 1125, keeping 1600×1125 = 1.4222).

## 6. Verification on device

1. `[nvn] WindowInitialize swap chain 3 textures, interval 1, first 1920x1350 format 0x…`
   (`dm/gfx/nvn/hle_nvn.c:1290`). Before the patch this line says `1920x1080`. The size is
   the immediate pair at `0x5ed308`/`0x5ed30c` (§2), so this line is the direct proof that
   the rows took.
2. Visual: with the canvas at 1.4222 the present ratio check (`nvn_mtl.m:11129`, 1 % rule)
   passes, the whole canvas is used with no bars, and the picture is no longer squeezed —
   the frame shows 25 % more vertical world.
3. If the game is forced into handheld mode, the second row keeps it consistent
   (1280×900 = 1.4222 as well).

## 7. Residual risk

`0x5ed2f0`'s descriptor is `{1920, 1080, 1, 1, format, …}` passed to a virtual create at
`[vtable+0x40]`. If the log still shows 1080 after the patch, that create clamps the size
(the surface may be constrained to the native window's size) — the next place to look is
the `nvnWindowBuilderSetNativeWindow` argument (`[x19+0x78]`, from the `nn::vi` layer
created before `0x5ed2f0`), i.e. whether the guest asks `nn::vi` for a layer of a
different size.

## 8. Reproducing the evidence

```sh
python3 dm/tools/nso.py <ExeFS>/main /tmp/bop_main.bin
python3 dm/tools/sdis.py /tmp/bop_main.bin 0x1ad70 40     # display-size selection
python3 dm/tools/sdis.py /tmp/bop_main.bin 0x1b320 20     # aspect getter
python3 dm/tools/sdis.py /tmp/bop_main.bin 0x5ed2f0 200   # swap-chain build
```

Slot names come from the resolver: each `adrp x1`/`add x1` pair names the proc stored by
the following `ldr x8,[x8,#slot]`/`str x0,[x8]`. Imported Horizon symbols come from the
dynamic section instead: `DT_JMPREL` (tag 23) entries map a GOT offset to a symbol index,
whose name is `nn::oe::GetOperationMode`, `nn::vi::CreateLayer`, `nvnBootstrapLoader`, …
